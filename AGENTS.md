# Repository working rules

- Implement only the requested stage.
- Read relevant existing code and documentation before editing.
- Never fabricate test results or performance measurements.
- Never weaken tests to hide a correctness failure.
- Do not commit, push, or create a remote repository.
- Explain important design decisions and report exact verification commands.
- Maintain `docs/progress.md` with completed work, limitations, and next steps.
- Use official Go, gRPC, and Raft references when resolving technical questions.
